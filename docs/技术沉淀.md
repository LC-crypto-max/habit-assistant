# 技术沉淀：Codex CLI 本地兴趣 Worker

## 设计目标

本项目把个人兴趣数据处理拆成三层：

1. 本地 worker：在用户授权后读取公开 URL 或模拟数据。
2. Agent Reach：读取公开页面内容，输出可解释的公开内容摘要。
3. Spring Boot：保存标准 behavior_event，生成画像和推荐。

这样做的核心目标是：让用户的数据仍然留在本机控制边界内，同时让 Codex CLI 参与“兴趣理解”，而不是让后端服务直接碰本机敏感数据。

## 为什么不让 Spring Boot 直接读取本机数据

Spring Boot 是服务端进程，不应该直接读取用户浏览器历史、应用窗口、Cookie、聊天数据库或本地文件。即使它运行在本机，也容易造成权限边界不清晰。

当前设计要求：

- 只有用户显式启动 worker，才会发生本地读取。
- worker 只读取授权范围内的公开 URL、标题、访问时间、访问次数或模拟数据。
- 后端只接收结构化 behavior_event，不接收 Cookie、Token、Session、聊天记录、通讯录、支付信息。
- 所有异常和入库错误都返回 JSON，避免 500 隐藏真实原因。

## 为什么 Agent Reach 放在本地 Worker

Agent Reach 可能依赖本地 CLI、代理、平台工具或用户手动配置。把它放在 worker 而不是 Spring Boot 内有几个好处：

- 用户可以在终端看到即将执行的命令。
- verbose 模式可以打印 Agent Reach 输入和输出。
- 后端不用保存任何平台凭据。
- 第一阶段可以 mock/dry-run，先跑通链路，再替换真实读取。

当前 mock 命令格式：

```text
[AgentReach] 即将执行命令: agent-reach read --url "<url>" --platform "<platform>" --dry-run
[AgentReach] 返回结果: {...}
```

路由：

- `bilibili` -> `read_bilibili`
- `youtube` -> `read_youtube`
- `xiaohongshu` -> `read_xiaohongshu_public`
- `github` -> `read_github`
- `web` -> `read_web_page`

## Codex CLI 的作用

Codex CLI 是本地兴趣分析器。它不负责采集数据，只基于 worker 传入的 `raw_items` 做结构化分析：

- 从标题、摘要、URL、公开内容类型中生成 `tags`。
- 识别 `contentType` 和 `interestCategory`。
- 生成 `summary`、`summaryForProfile`、`recommendationHints`。
- 给出 `confidence` 和 `dataLevel`。

安全约束：

- 不允许读取文件系统。
- 不允许读取 Cookie、Token、Session、账号密码、聊天记录、私信、支付记录。
- 不允许调用外部网络。
- 如果原始数据没有 URL，不允许编造 URL。
- 输出必须是 JSON。

如果 Codex CLI 不存在、超时、输出非 JSON、包含敏感字段或编造 URL，worker 会回退到 Agent Reach enrichment 的结果。

## 完整处理链路

```text
Spring Boot 创建任务
  -> worker 领取任务
  -> worker 读取授权 URL 或 browser_history_sample.json
  -> agent_reach_adapter.enrich_public_url(item)
  -> Codex CLI 分析 raw_items
  -> worker 生成标准 behavior_event JSON
  -> POST /api/v1/behavior-events/batch
  -> BehaviorEventController
  -> BehaviorEventService
  -> ActivityService
  -> UserActivity 数据库表
  -> ProfileService / RecommendationService
```

推荐调试命令：

```powershell
py -3 scripts/codex_query_worker.py --once --yes --use-codex-cli --direct-behavior-batch --verbose
```

verbose 会打印：

- 当前任务
- 采集到的 raw items
- Agent Reach 命令和输出
- Codex CLI 命令、输入和输出
- behavior_event JSON
- 后端 POST URL 和响应

## 标准 Behavior Event

worker 和后端统一使用以下字段：

```json
{
  "userId": "me",
  "eventType": "VISIT",
  "platform": "github",
  "source": "codex-cli-analysis",
  "url": "https://github.com/openai/codex",
  "title": "OpenAI Codex repository",
  "summary": "Public GitHub repository.",
  "tags": ["github", "codex"],
  "contentType": "repository-or-code-page",
  "interestCategory": "developer-tooling",
  "confidence": "HIGH",
  "dataLevel": "PAGE_VISIBLE_CONTENT",
  "detectionReason": "public_url_enrichment",
  "rawEvidence": {
    "domain": "github.com",
    "adapter": "agent-reach",
    "adapterMode": "mock",
    "originalSource": "agent-reach-enrichment"
  },
  "occurredAt": "2026-06-12T10:00:00"
}
```

兼容字段：

- 后端接受 `type` 或 `eventType`。
- 后端接受 `contentCategory` 或 `interestCategory`。
- `tags` 是数组，对应 Java `List<String>`。
- `rawEvidence` 是对象，入库时保存为 JSON 文本。
- `occurredAt` 使用 ISO-8601；`createdAt` 可作为兼容别名。

## 500 问题排查过程

曾经的 500 风险主要来自四类问题：

1. JSON 字段不匹配：前端或 worker 发 `eventType`，后端只认 `type`。
2. 时间格式不匹配：客户端发带时区 ISO-8601，DTO 使用 `LocalDateTime` 直接解析失败。
3. 对象/数组字段不匹配：`tags`、`rawEvidence` 没有统一处理。
4. 字段长度过短：`text`、`rawEvidence` 使用普通 varchar，较长 JSON 可能写库失败。

修复结果：

- `BehaviorEventRequest` 支持 `eventType`、`createdAt`、`interestCategory` 别名。
- `occurredAt` 支持本地或带时区 ISO-8601。
- `tags` 使用 `List<String>`。
- `rawEvidence` 经过白名单和长度限制后保存为 TEXT/CLOB。
- 全局异常响应包含 `success=false`、`message`、`path`。
- MockMvc 覆盖标准 behavior_event JSON，目标接口返回 200 OK。

## 安全边界

禁止读取或保存：

- Cookie、Token、Session、Authorization Header
- 账号密码、验证码
- 微信聊天数据库、聊天记录、私信
- 通讯录、支付记录
- 平台私有接口和受保护内容

允许处理：

- 用户主动提供的公开 URL
- 浏览器历史中的 URL、标题、访问时间、访问次数
- App 名称、包名、使用时长、打开次数
- 用户授权目录下的本地笔记
- 公开页面的 title、description、keywords 或摘要

## 后续优化方向

- 将 Agent Reach mock 替换为真实平台读取，但保持 dry-run 和 verbose。
- 为 worker 增加更细粒度的用户确认提示。
- 给 behavior_event 增加独立数据库迁移脚本，替代 H2 best-effort 兼容初始化。
- 将 Codex CLI prompt 独立成模板文件，便于版本化。
- 增加端到端测试：创建任务 -> worker dry-run -> direct behavior batch -> profile/recommendation。
- 为 `rawEvidence` 增加 schema 文档和字段版本号。
