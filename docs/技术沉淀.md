# 技术沉淀：多用户兴趣画像与推荐平台

## 1. 阶段目标

项目从本地个人助手升级为小规模在线协作平台。多个用户可以在同一个 URL 提交数据，系统按用户沉淀画像并生成推荐。

## 2. 核心链路

```text
浏览器 / PowerShell / 微信小程序 / 飞书机器人
  -> REST Controller
  -> Service 业务层
  -> Repository
  -> H2 或 MySQL
```

## 3. 多用户隔离

当前使用 `userId` 作为轻量身份标识。行为、画像、推荐都存储 `userId`：

- `UserActivity.userId`
- `InterestTerm.userId`
- `Recommendation.userId`

正式上线后，应增加登录鉴权，由服务端从登录态解析用户，而不是长期信任前端传入的 `userId`。

## 4. 画像和推荐

行为进入 `ActivityService` 后会抽取关键词并更新兴趣词权重。`RecommendationService` 读取兴趣词，调用多个 collector 获取候选内容，再按命中兴趣词、发布时间、搜索关键词和显式反馈等规则打分。

已有 collector：

- Mock 内容源
- 用户访问记录内容源
- RSS/Atom
- 配置化 JSON API
- X Recent Search

### 4.1 推荐排序升级

当前推荐分数由几类信号组成：

- 画像兴趣词：标题命中权重最高，摘要命中次之，标签命中再次之。
- 临时搜索词：`POST /api/recommendations/search` 会把关键词记录为搜索行为，并在本次推荐中提高相关内容分数。
- 新鲜度：6 小时、24 小时、7 天内内容分别获得不同加分。
- 显式反馈：`LIKE`、`FAVORITE`、`READ` 提升相似平台和标签；`DISLIKE` 降低相似内容；`BLOCK_SOURCE` 过滤同平台候选。

反馈更新后，系统会额外写入一条用户行为，让画像层继续学习。这样下一次推荐既看长期兴趣，也看用户刚刚表达的喜好和厌恶。

### 4.2 本地采集边界

浏览器历史和本机应用检测属于高敏感数据，当前采用显式脚本触发，不做静默后台读取：

- `scripts/import-browser-history.ps1`：复制 Chrome/Edge 历史 SQLite 文件，读取最近 URL 并写入 `/api/visits`。
- `scripts/collect-app-usage.ps1`：检测指定进程或窗口标题，例如哔哩哔哩客户端，命中后写入 `/api/activities`。

这一设计方便本地验证，也保留了上线时的合规边界：多用户协作场景下应由用户主动上传数据，或通过清晰授权后的客户端采集。

## 5. 动态推荐刷新

推荐不再只按自然日缓存，而是根据用户活跃度动态过期。

默认策略：

```text
近 24 小时 < 20 条行为：12 小时刷新
近 24 小时 20 到 79 条行为：6 小时刷新
近 24 小时 >= 80 条行为：3 小时刷新
```

配置项：

```yaml
assistant:
  recommendation-refresh:
    activity-window-hours: 24
    medium-activity-threshold: 20
    high-activity-threshold: 80
    low-activity-hours: 12
    medium-activity-hours: 6
    high-activity-hours: 3
```

接口：

- `GET /api/recommendations/today`：返回今日推荐；如果已过期则自动刷新。
- `POST /api/recommendations/refresh`：强制刷新推荐。
- `GET /api/recommendations/refresh-policy`：查看当前用户命中的刷新策略。

## 6. 在线协作部署

推荐第一版线上架构：

```text
Nginx + HTTPS
  -> Spring Boot Jar
  -> MySQL
```

MySQL 是线上数据底座，用于保存用户行为、画像、推荐和反馈。H2 只保留本地开发使用。

上线建议：

- 使用 HTTPS 域名。
- 开启 MySQL 定时备份。
- 使用环境变量管理数据库密码和飞书 webhook。
- 为接口增加登录鉴权和简单限流。
- 小程序上线时使用微信登录态绑定内部用户。

## 7. 中间件演进

- Redis：缓存画像 Top N、推荐结果、限流计数。
- RabbitMQ/Kafka：采集、画像更新、推荐生成异步化。
- Elasticsearch/OpenSearch：候选内容多时做全文检索和召回。
- 对象存储：保存用户上传 CSV 和历史导出文件。

## 8. 测试策略

优先使用不占用 8080 的 MockMvc 测试：

```powershell
mvn -DskipTests compile
mvn test
```

测试 profile 使用 H2 memory，并关闭定时任务和真实外部采集：

```text
src/test/resources/application-test.yml
```

真实 jar 验证使用后台脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
```

如果 Windows/Java 25 环境下后台脚本健康检查超时，优先使用 MockMvc 测试作为代码级验证；脚本可通过 `-StartupTimeoutSeconds 45` 放宽启动等待。不要用前台 `java -jar` 做自动化验证。
